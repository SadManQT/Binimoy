# Handoff: LP-021 eleven-category catalog, with the LP-008 provider and LP-017 objective release it needed

- Base: `main` after LP-013
- Branch: `chunk-catalog`
- Date: 2026-10-12
- **Partly done.** All eleven categories run end to end on a synthetic provider, at the database level, in all three service modes. One category has a browser test. Nothing here has touched a real provider.

## Implemented

- `@lp/templates`: eight new templates (`game_account`, `game_topup`, `saas_subscription`, `gift_card`, `source_code`, `domain_website`, `course_access`, `service_milestones`), so every `CAT-01` to `CAT-11` has one. Twelve new predicates. A predicate can be bound to an agreement field (`bindsField`): the provider's fact only counts for exactly that destination.
- Capability registry: every `mock_*` capability is `MOCK_TESTED`; `secret_vault` is `LIVE_TESTED` (a real Synapse, local only).
- `@lp/db/verification`: the synthetic provider (`setMockFact`, `getMockFacts`), `verifyPackage`, `verifyDeal`, `sweepVerifications`. No fact means `UNKNOWN`. A changed answer is recorded as a new result; the old one stays.
- **Objective release** (B9): `game_topup` and `course_access` only. When every mandatory item is independently proven a challenge window opens (24 h); a dispute or a lost proof closes it; its end authorizes `OBJECTIVE_RELEASE`.
- **Milestones** (C14.12): `service_milestones` deals carry 1 to 6 priced milestones that sum to the price. Each is delivered, inspected, accepted and paid on its own.
- Worker: runs `sweepVerifications` every tick.
- Web: eleven categories on "new deal", milestone rows, a plain delivery form for categories with nothing secret, the proof source beside each checklist line, the challenge-window notice, and a Scenario Lab panel on the deal page where a party sets what the fictional provider answers.

## Honesty notes

- **This chunk was not test-first.** `verification.ts`, the delivery changes and the templates were written before `catalog.int.test.ts`. The mutation check above is the evidence that the tests can fail.
- One existing test (`V7-13`) failed after my first change to replacement logic; that was a real regression in my change and is fixed.
- `research.int.test.ts` "failing search provider" failed once in one full run and passed in every run since. I could not reproduce it and do not know the cause.
- The integration suite was run on a local Postgres container (`binimoy-test-pg`, port 54330) through `TEST_DATABASE_URL`, not on Supabase, because 99 cases at Supabase latency take too long. CI runs the same suite on its own Postgres.
- The 99 cases call the database functions directly. Only the top-up category was driven through the browser.

## Not run

- Any real provider, registrar, issuer, publisher or build runner.
- Browser tests for the other ten categories.
- Proof freshness expiry: a result older than `freshnessHours` is re-asked by the sweep, but no test ages a result (results are append-only and there is no injected clock).
- Independent review.

## Not built

- **Real independent verification of anything.** Every "independent fact" is whatever a party to the deal typed into the Scenario Lab. That is right for a prototype and would be a hole anywhere else: in a real environment the lab must not exist. Nothing gates it on environment today because `VERIFIER_MODE` can only be `mock`.
- **Sandboxed build or test of delivered source code** (CAT-08, D.9). `mock_build.tests_pass` is a typed-in fact; no code is executed.
- **Malware scanning** of delivered files (INV-12). The risk text says so.
- **Change orders and revision limits** for milestone deals. Scope is fixed at funding; `correctionAttempts` is stated in the terms and not enforced.
- **A deadline for later milestones.** The no-delivery refund covers only a deal where nothing was ever delivered.
- **Category-specific post-delivery claims** (later revocation, recovery by the original owner): they can be raised as a dispute after dispatch, which records the claim and promises nothing.
- **Notices.** The challenge window is shown on the deal page; nobody is actively told (LP-018).
