# Handoff: LP-005 Ledger, mock funding and outbox

- Base: `main` after the LP-001 to LP-004 merge
- Branch: `chunk-money`
- Date: 2026-10-12

## Implemented

- **Double-entry journal** (`journal_entry`, `journal_line`): append-only, one entry per economic fact keyed by a unique `ref`, and a deferred database trigger that rejects any unbalanced entry at commit.
- **Balances from the journal** (`dealBalances`): received, held, reserved, seller paid, buyer refunded, fees, unapplied, plus a conservation flag (D.4).
- **Funding invoice** (`createInvoice`): buyer only, only for an `ACCEPTED` agreement, bound to the exact agreement version, amount and currency. One active invoice per deal.
- **Mock funding** (`startFunding`): refuses anything but mock mode.
- **Provider events** (`ingestPaymentEvent`, `processPaymentEvent`, `sweepPaymentEvents`): HMAC over the raw body, stored before processing, deduplicated by event ID and again by the underlying payment.
- **Invoice expiry** (`expireInvoices`) on the database clock.
- **Outbox leases** (`claimOutbox`, `completeOutbox`, `failOutbox`): fencing generation, bounded attempts, dead letter.
- **Deal lock**: every command now locks the deal row first, then the aggregate (D.5 single lock order). `systemTransition` lets one command cause a transition on another aggregate of the same deal inside its own transaction.
- **Withdrawal guard**: an agreement can be withdrawn only while nothing has been paid; an unpaid invoice is cancelled with it.
- **Orphaned transactions**: every connection sets a 30-second idle-in-transaction timeout.
- **Web**: funding section on the deal page, a mock provider chooser, and `POST /api/webhooks/mock-payment`.
- **Worker**: heartbeat, invoice expiry, payment event sweep, outbox drain.

## Problem found and fixed

A test process that died mid-call left a database session "idle in transaction" for six minutes, holding locks that blocked later work. The Supabase pooler did not roll it back. Connections now carry a server-side idle-in-transaction timeout, and a test asserts the setting is in force.

## Limitations

- **No money can leave the held balance yet.** Reservations, authorizations, payout and refund dispatch are LP-009. Unapplied funds are recorded as owed back to the buyer, but nothing returns them yet.
- **`RECONCILIATION_REQUIRED` is a dead end for now.** There is no operator action to resolve it; the buyer cannot create a new invoice while the mismatched one is active.
- Fees are always zero. Fee postings are not implemented.
- The mock provider's signing secret is derived from `AUTH_SECRET`.
- The outbox has no handlers, so entries are only acknowledged. Notifications arrive with LP-018.
- Integration tests against Supabase from this machine are slow (several minutes) because of network latency.
