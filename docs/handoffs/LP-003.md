# Handoff: LP-003 Auth, sessions and consent records

- Base: head of `lp-002-contracts`
- Branch: `lp-003-auth`
- Date: 2026-10-12

## Implemented

- Authentication through Better Auth 1.7.7 (ADR-003): email and password, magic link, email one-time code, phone one-time code, optional Google, Facebook and GitHub, and the two-factor plugin.
- `actorFromHeaders`: the only path from a request to an actor for `executeCommand`.
- Web: `/login` with every option in Bangla, `/account` with the session list, sign-out and sign-out-everywhere, `/api/auth/*`, and a local-only `/dev/messages` page showing links and codes.
- Monitoring consent records (D.8): `recordMonitoringConsent`, `withdrawMonitoringConsent`, `monitoringAllowed`.
- Staff roles (D.2): `grantStaffRole`, `revokeStaffRole`, `activeStaffRoles`, with history kept.
- Config: `APP_URL`, `AUTH_SECRET` (32 characters or more), and paired social credentials.

## Contract and migration changes

- Migration `0004_auth_and_consent.sql`, applied to Supabase. `app_user` gained `name` and `email` (both required), so inserting a bare user no longer works.
- New required environment variables: `APP_URL`, `AUTH_SECRET`.

## Problem found and fixed

Better Auth disables its origin check when it detects a test environment. The first test run accepted a foreign-origin sign-out. The check is now forced on in `createAuth`, and the test passes for the right reason.
