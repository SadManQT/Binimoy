# Handoff: LP-018 to LP-022 slices (notices, operations, receipts, safe retrieval, evaluation, lab)

- Base: `main` after LP-021
- Branch: `chunk-operations`
- Date: 2026-10-12
- **Each of these work packages is partly done.** This handoff covers one slice of each, not their completion.

## Implemented

- **Notices (LP-018, FE-23).** `@lp/db/notices`: recorded events become in-app notices (`deliverOutbox`, run by the worker), one per event and recipient. `/notifications` lists them. A notice carries a kind, a deal and a state name; never message text, claim text or a secret.
- **Notice-gated objective release (D.6, V7-15, V7-16).** The challenge period has no end time until an authenticated page has shown the buyer the notice. A changed proof removes the window; when the proof returns a new notice is issued and must be shown again.
- **Operator pauses (LP-022, D.13, V7-38).** `@lp/db/ops`, `pnpm ops status|pause|resume`. Four independent pauses: funding, settlement dispatch, research, AI. Each change is recorded with who and why. `/api/health` now reports pauses, outbox backlog and age, dead letters, unreconciled operations and waiting settlements.
- **Receipts (FE-24).** `@lp/db/receipt`, `/deals/[id]/receipt`: agreement version and hash, every package version, each check with its proof source, every allocation and transfer state, balances, and a "not final" flag. Parties only.
- **Safe retrieval (LP-020, D.9, V7-26).** `httpRetriever` in `@lp/adapters`: http/https only, default ports, no credentials, every resolved address must be public (IPv4 and IPv6), every redirect re-checked, no cookies, size and time limits, a login form is a wall.
- **Live search adapter.** `tavilySearchProvider`. With `RESEARCH_MODE=live` and `SEARCH_API_KEY` the lookup uses it with the safe retriever. Page fetches run six at a time.
- **Evaluation (LP-022, FE-26).** `pnpm eval:ai` with a held-out set in `evals/` (41 labelling cases, 10 identity cases).
- **Scenario Lab data (FE-25, V7-36).** `pnpm demo:seed`, `pnpm demo:reset`, and `DB_SCHEMA` so the app can run on the lab's own schema `lp_lab`. The tools refuse any other schema, production, and any non-mock payment mode.
- **Requirements check (V7-01, INV-16).** A unit test fails when a requirement claims progress without existing files, a test and evidence, or when anything is marked verified by this repository itself.
- `Dockerfile` for the web and worker processes; `pnpm --filter @lp/worker start`.

**The keyword sorter is not fit to label real posts.** It was right on the 12 fixture pages because they were written beside it. The held-out set was not used to tune it. In live mode nothing is labelled at all, because the author of a fetched page is unknown; that is the honest behaviour until a model does this job.

## Honesty notes

- Two real bugs were found by the safe-retrieval tests: Node's block list matched every IPv4 address against the IPv4-mapped IPv6 range (so every public address was refused), and awaiting the cancel of a partly read response hung.
- The DNS answer is checked and then resolved again by `fetch`. A hostile DNS server could answer differently the second time. This needs an egress rule or address pinning before live use; the code says so.
- The requirements check, on its first run, found eleven rows claiming progress with no evidence listed. They now point at their handoffs.
- The demo accounts were created through the auth library; nobody has signed in with them in a browser.
