# Handoff: LP-011 AI deal assessment

- Base: `main` after LP-006
- Branch: `chunk-ai`
- Date: 2026-10-12
- **LP-011 is partly done.** The pipeline around the model is built and tested with a fixture and with scripted models. No real model has been called.

## Implemented

- `@lp/domain`: `assessmentSchema` and `validateAssessment` (shape, citations, claim-versus-fact, no verdicts or tone reasoning).
- `@lp/adapters`: `AssessmentModel` interface, `fixtureAssessmentModel`, `claudeAssessmentModel` (Claude Opus 5.5 via the official SDK), `PROMPT_VERSION`.
- `@lp/adapters/assessments`: `requestAssessment`, `cancelQueuedAssessments`, `buildContext`, `runAssessmentJobs`, `getAssessment`.
- Worker runs assessment jobs with the model chosen by `AI_MODE`.
- Web: assessment section on the deal page (dashed border, "suggestion, not a decision", model name, stale marker, outage and rejection messages) and read-only on the reviewer's case page with a note that the reviewer need not agree.
- ADR-007.

## Honesty notes

- `assessments.ts` (the orchestration) was written before its test file. Its tests passed on first run and were not seen failing. The validator was test-first.
- The fixture model always produces valid output, so the "grounded" test shows the pipeline stores and binds correctly, not that a real model stays grounded.

## Not run

- **Any call to Claude or any other real model.** Prompt quality, grounding rate, refusals, latency and cost are all unmeasured.
- The evaluation set the spec requires (B13, `pnpm eval:ai`): not built.
- Independent review.

## Not built

- **AI guidance during delivery and diagnosis** (B8 login-problem workflow, missing-field questions when drafting an agreement, B5 step 2). Only the case assessment exists.
- **Automatic triggers** (at delivery, failed inspection, dispute). Assessments run only when a party asks.
- **Rolling summaries for long conversations.** Beyond 200 messages the older ones are dropped and reported as a coverage gap.
- **AI activity timeline** (FE-14) beyond the single latest assessment and job status.
- **Switching to a live model safely:** a new consent policy version naming the provider, and re-consent. See ADR-007.
- **Refusal fallbacks**, prompt caching, cost budgets.

## To use a real model later

1. Put an Anthropic API key in `.env` as `MODEL_API_KEY` and set `AI_MODE=live`.
2. Before doing that for anyone but yourself, the consent text must name the provider (ADR-007).
