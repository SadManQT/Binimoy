# Handoff: LP-014 slice (design system, shop directory, alerts, 3D front page)

- Base: `main` after the founder guide (PR #15)
- Branch: `chunk-design`
- Date: 2026-10-12
- **LP-014 is partly done.** This is the first pass of the integrated interface, plus the shop features the founder asked for on the same day (ADR-009).

## Implemented

- **Shop backend** (`@lp/db/shops`): `listShops`, `getShop`, `shopCategoryCounts`, `listAlerts`, `createSafetyAlert`, `retractSafetyAlert`. Community reports gained a reviewer rating, an alleged issue and a shop category; one live report per person per shop (`DUPLICATE_REPORT`).
- **Pages**: `/shops` (search, ten categories, two sort orders), `/shops/[id]` (evidence panel, type bar, reviews with replies), `/alerts` (moderators' warnings and published complaints), all readable without signing in. The moderation page can publish and retract general warnings. The report form has rating and issue fields.
- **Design system** (`apps/web/app/globals.css`): one dark ink-and-teal theme (C36.1), Anek Bangla for headings and Hind Siliguri for text, tokens, panels, rows, chips with words, forms, banners, print styles, reduced-motion handling. A site header with navigation, and a permanent line on every page saying this is a test build.
- **Deal page**: a "what to do now" panel with the five stages; beside the content on desktop, pinned to the bottom on phones (C36.2). Its text comes from `nextStep`, a tested pure function that never calls an unfinished transfer complete (C36.3).
- **Front page**: shop search first, then recent complaints, categories, how reporting works, a scroll-driven explanation of a deal, and a section on what the product does not claim. All listed content is real published data, with stated empty states.
- **3D**: one strongbox model generated with Tripo (30 credits), reduced from 4.2 MB to 705 KB, shown with three.js. Rings, coins and a key are built in code and move through four states as the deal explanation scrolls. three.js loads only on the front page, only when the scene is near the screen. A 52 KB still image is shown first and stays when WebGL is missing, the model fails, or the visitor asked for reduced data. With reduced motion the scene renders single still frames.
- **Practice data**: `pnpm demo:reset` now also creates four invented shops with reviews, a complaint with a reply and a resolution, and one general warning.
- `output: "standalone"` removed from the Next config: nothing used it and it copied several hundred megabytes on every build.

## Honesty notes

- The shop test first failed because its own warning title contained a 13-digit number, which the identifier rule correctly refused. The test was changed, not the rule.
- That failed run left one published test report in the Supabase database. It was withdrawn by `packages/db/src/e2e-cleanup.ts`, acting as its author. Browser tests still run against the real development database, so an aborted run can leave test rows behind again.
- Visual review was done by me from screenshots at 1440 and 390 pixels wide, in headless Chromium with software rendering. No person has looked at it, and it has not been opened in Safari, Firefox or on a real phone.
- The automated accessibility check covers four public pages. It is not a screen-reader test and does not establish WCAG conformance (D.12).
- The disk on the development machine filled up during this work (about 200 MB free). A 1.66 GB container image built earlier the same day was removed to continue.

## Not built

- Restyling of the less-used screens beyond what the shared styles give them (review workbench, receipt, conversation). They use the system but were not individually designed.
- Page transitions, loading skeletons, and realtime updates.
- A light theme.
- Shop category correction by moderators; merging two names for one shop.
