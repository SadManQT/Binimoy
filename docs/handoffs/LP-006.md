# Handoff: LP-006 Monitored conversation and evidence versions

- Base: `main` after LP-010
- Branch: `chunk-conversation`
- Date: 2026-10-12

## Implemented

- **One monitored room per deal** (`packages/db/src/conversation.ts`), open once both parties are in the deal. It is server-readable by design and the page says so in a persistent label: not private, readable by the assigned reviewer, processed by AI only with both parties' consent, off-platform chat not captured.
- **Consent (D.8):** a party cannot post before accepting the monitoring policy (`monitoring-v1`: purposes, model destination, attachment classes). `aiMayRead` is true only while both parties' consents are active. Withdrawing stops AI reading and the withdrawer's posting; reading, dispute filing and the other party's messages are unaffected.
- **Versions (B3):** an edit or a deletion adds a version. Earlier text stays on record. Only the author revises their own message.
- **Durable cursor (D.12):** each version has a sequence number. Reading "after" a cursor returns only messages that changed since, whole, so a reconnect neither misses nor repeats.
- **Secrets:** a message that looks like a password, one-time code, PIN or card number is refused before it is stored. Either party can flag a message that slipped through: its text is removed from every version and a private incident row is recorded without the secret.
- **Scoped reading (D.2):** the two parties, plus the reviewer currently assigned to a dispute on the deal. A reviewer reads only; nobody else gets anything.
- **Web:** deal-room section on the deal page; read-only on the reviewer's case page.

## Honesty note on test order

`conversation.ts` was written before its integration test file, not after a failing test. The secret heuristic and every other module in this chunk were test-first. The conversation tests passed on first run, so they were never observed failing; they assert on real database state, but that is weaker evidence than a watched failure.

## Not built

- **AI reading the room.** Nothing consumes `aiMayRead` yet. That is LP-011, along with cancelling queued analysis on withdrawal and discarding late results (V7-19 in full).
- **Attachments.** No uploads, so no quarantine, scanning or redacted derivatives (D.9). The policy lists no attachment classes.
- **Realtime.** The page shows messages on load. The cursor exists for a future push or poll; nothing uses it in the browser yet.
- **Rolling summaries and exact-message citation** (B3) belong with the AI work.
- **Retention and purge** of messages (D.8).

## Limitations

- The secret heuristic is deliberately simple. It misses secrets without a keyword and can flag harmless sentences. The UI says so.
- Redaction cannot recall a secret from whoever already read it. The UI tells the owner to change it at the provider.
- A deleted message's earlier text is still visible in its history to the other party and the reviewer. Only a secret flag removes text.
- The first incident row is the whole "private incident handling": there is no operator view of incidents.
