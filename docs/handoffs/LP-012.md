## Implemented

- `@lp/domain` `research.ts`: `planQueries` (12 queries: neutral, favourable, unfavourable and follow-up, in English, Bangla and Banglish), `canonicalUrl`, `duplicateKey`, `classifyPassage` (keyword sorter), `matchSubject`.

- Web: `/research` (form, past lookups) and `/research/[id]` (coverage statement, counts with their caveats, cards, "possibly related" section, per-card correction button). Bangla.

## Honesty notes

- The integration test was written before `research.ts` in adapters, but it was only seen failing as "module not found", not assertion by assertion. One assertion failed on first real run because the test's own link matcher was wrong; the test was fixed, not the code.
- The browser test passed on its first run and was never seen failing.
- `classifyPassage` is a keyword list. It is right on the 12 fixture pages because they were written alongside it. It says nothing about accuracy on real posts. Every card it labels shows "sorted by keyword, may be wrong".
- "Summary" is the first 280 characters of the page's own text. No model rewrites or translates anything.

## Not built

- **A live `SearchProvider`** (Tavily, Exa or other; not chosen, needs a key and a founder decision).
- **A real retriever with the D.9 network controls** (private-address denial, DNS and redirect revalidation, size and time limits). Nothing fetches untrusted URLs today, so the controls are untested rather than missing in use. This must exist before any live fetch.
- **Model-written attributed summaries and translation** (C7.1, C34.3).
- **Links between a report and its replies or updates** (C8 `related_report_ids`, FE-05). The seller reply and the refund update appear as separate cards.
- **Aliases, previous names, ownership changes; a link or domain as the subject** (C7.2). A subject is a name as typed.
- **Source drawer with passage IDs, filters, sort options, two-subject comparison** (FE-04, FE-06).
- **Shared cache of public source bytes.** Every lookup stores its own snapshots.
- **User-supplied excerpts** (`USER_SUBMITTED`).
- Lookups run inside the web request. A live search will need to move to the worker.
