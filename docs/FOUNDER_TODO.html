2. See it running (10 minutes, no accounts needed)

This uses a separate practice area of the database called the lab, so it cannot touch your other data.

  1. Open the Terminal app and go to the project: 
    cd ~/Binimoy
  2. Make sure Docker Desktop is open (the whale icon in the menu bar). The vault needs it.
  3. Create the practice data. This prints four email addresses and one password: 
    DB_SCHEMA=lp_lab pnpm demo:reset
    If a safety prompt asks you to confirm, say yes. It only rebuilds the lp_lab practice area and refuses to run on anything else.
  4. Start the app on the practice area: 
    DB_SCHEMA=lp_lab pnpm dev
  5. Open http://localhost:3000/login. Sign in as the buyer address in one browser and the seller address in a private window. Password: binimoy lab 2026.
  6. Open "আমার ডিল". You will find three deals:
    • Lab 1: a license deal, agreed, waiting for the buyer to pay (fake).
    • Lab 2: a game top-up where the pretend supplier says it sent to the wrong player. Use the "পরীক্ষাগার" panel on the deal page to change what the supplier says and watch the checklist change.
    • Lab 3: a design job in two milestones.
  7. Open /shops and /alerts. The practice data has four invented shops with reviews, one complaint with the shop's reply and a resolution, and one general warning.
  8. Also try /research (type Tech Bazar BD), /community, and as the moderator account /moderation.
Tested: I signed in with the practice buyer and seller accounts in a browser against a local database, and it worked. Each reset prints new email addresses.

4. Task A: real web search

do soon15 minutes

What it is

A search service finds public posts that mention a shop's name. The code for one service, Tavily, is already written. It has only been tested against a pretend reply, never the real service.

Way 1 (ready now): Tavily

  1. Go to tavily.com, create an account, and copy your API key (it starts with tvly-).
  2. Look at their pricing page for the current free allowance. One seller lookup uses 12 searches (12 credits at the "basic" depth).
  3. In .env set these two lines: 
    RESEARCH_MODE=live
SEARCH_API_KEY=tvly-your-key-here
  4. Restart the app (Ctrl+C, then pnpm dev).
  5. Open /research. The page should say "আসল ওয়েব সার্চ চালু". Search for a real page name.
  6. Tell me what you saw. I expect to fix things after the first real run.

Way 2: another service (Exa, Brave Search, Google Programmable Search)

Possible, but I have to write and test a new adapter for it first. Tell me which one and give me a key the same way.

What to expect, honestly

  • Facebook posts in private groups or behind a login will show as "link only". The app does not and will not go around login walls.
  • In live mode the cards will not say "complaint" or "good experience". The app cannot tell who wrote a page, and the simple word-matching sorter is too weak for real posts (see section 9). That needs the AI key from Task B and more work from me.
  • Before this is opened to other people, the server needs a firewall rule that blocks outgoing requests to private addresses. I will set that up with the hosting in Task D.

7. Task D: put it online privately

needed before anyone else uses it1 to 2 hours, with me

What has to run

  1. The website (one container).
  2. The worker (same container image, different start command). It sends payouts, runs timers and makes notices. Without it deals get stuck.
  3. The database: you already have it on Supabase. Nothing to do.
  4. The vault server (Matrix "Synapse"). It needs a small always-on machine and its own address such as vault.your-domain. Without it, deals that hand over a secret cannot be delivered.

Way 1 (my recommendation): one small server that runs Docker

One machine from a provider such as Hetzner, DigitalOcean or Vultr runs the website, the worker and the vault. About 2 GB of memory is a sensible start; check current prices on their sites.

  1. Buy a domain if you do not have one.
  2. Create the server (choose Ubuntu, the smallest size with 2 GB memory, a region near Bangladesh such as Singapore).
  3. Give me access the safe way: add an SSH key, do not send a password in chat. I will tell you how at that point.
  4. In your domain's DNS add two "A" records pointing to the server's address: one for the app, one for the vault.
  5. I install Docker, the three services, HTTPS certificates and the firewall rules, then run the checks and report.

Way 2: a hosting platform (Railway, Render, Fly.io)

Less server care, usually higher monthly cost. You create two services from the same GitHub repository: the website and the worker. The vault server still needs somewhere to live; these platforms can run it, but it needs a disk that is kept.

Way 3: Vercel for the website

I do not recommend it here. Vercel cannot run the always-on worker or the vault, so you would still need a server for those.

8. Tasks E to I

E30 minutes

Logins: fix Facebook, and make apps for the online address

The Google, Facebook and GitHub login apps you made work only for http://localhost:3000. The online copy needs its own, with this return address in each:

https://your-app-address/api/auth/callback/google
https://your-app-address/api/auth/callback/facebook
https://your-app-address/api/auth/callback/github
  • Google (console.cloud.google.com → Credentials): the consent screen is in "Testing", so only test users you list can sign in. To let anyone sign in, press "Publish app" on the OAuth consent screen. Then create a new "Web application" client with the return address above.
  • GitHub (github.com → Settings → Developer settings → OAuth Apps): "New OAuth App", homepage is your app address, callback is the GitHub line above.
  • Facebook (developers.facebook.com → My Apps): this is the one that gave you an error. The usual causes are: the app is still in "Development" mode (only you can log in), the return address is not listed under Facebook Login → Settings → "Valid OAuth Redirect URIs", or the "email" permission is not added. Send me the exact words of the error and I will tell you which. If it stays painful, the simplest way is to switch Facebook login off; tell me and I will.

Put each ID and secret into the host's settings as GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, and the same pattern for FACEBOOK_ and GITHUB_. A login button appears only when both of its values are set.

F5 minutes

Give staff roles to real people

Nobody can make themselves a reviewer or moderator inside the app. You grant it from the terminal, after the person has created an account:

pnpm staff grant person@example.com reviewer "handles disputes"
pnpm staff grant person@example.com moderator "checks community reports"
pnpm staff list person@example.com
pnpm staff revoke person@example.com reviewer
  • A reviewer decides disputes at /review. A reviewer cannot take a case on a deal they are part of.
  • A moderator decides whether community reports are published, at /moderation.
  • You need at least two reviewers and two moderators, because an appeal must go to a different person.

Emergency switches, also from the terminal:

pnpm ops status
pnpm ops pause funding "reason"      # also: settlement, research, ai
pnpm ops resume funding "reason"

H15 minutes

Free disk space on your Mac

While I was working the disk reached about 200 MB free out of 228 GB, and a build failed because of it. I removed one thing I had made myself (a 1.66 GB container image) to continue. The rest is yours to decide. The biggest items I could see:

  • Docker's disk is about 31 GB. Inside it, an Oracle database image is 13 GB. If you no longer need it: open Docker Desktop → Images → delete it.
  • In Docker Desktop → Settings → Resources you can also lower the disk limit or press "Clean / Purge data" (this removes all containers and images, including your other project's).
  • On the Mac: Apple menu → System Settings → General → Storage shows what else is large.

Aim for at least 10 GB free. Other things on the machine:

  • I did not touch your other project's containers (cholo-…) or its Supabase project.

Trust signal: built

You told me this is a student research project and to go ahead, so each shop with three or more published reviews now shows a trust signal: a level (good signals, mixed signals, be careful) and a number out of 100. Below three reviews it says "not enough data".

10. Real money: not a coding task

The app cannot move real money and I will not make it do so. It refuses to start with any payment mode other than "mock". Do not describe it to anyone as escrow or as protecting their payment.

Before real money is even possible, these have to exist. None of them is something I can do for you:

  • Advice from a lawyer in Bangladesh on whether a company may hold buyers' money for sellers, and under what licence.
  • A payment partner (a bank or a licensed payment company) willing to hold the money and pay out on instruction.
  • Rules for refunds, chargebacks, fees and tax.
  • People to answer support and decide disputes every day.

When you have a partner and their technical documents, I can write the connection to them and test it in their sandbox.
